The tag vocabulary

Tags are defined here and nowhere else, so the list stays fixed and typos cannot create new ones by accident. A mod may wear any number of tags; you put them on from the Mods tab or a mod's own page. Name a tag whatever you like — it may not contain : or ;, may not look like a config name (-4- Something) and may not start with punctuation, which is how Mod Manager writes its own markers. -- Disabled is built in: put a mod on it to keep the mod installed and filed but leave it out of every config, and out of the dependency checks.
The order here is the order the tag lines appear in the config file. Each config picks its own order for the tags it uses, on the Configs tab; this one is only the fallback the Mods tab reads by when no config is chosen.

Configs are synthetic tags

You never list mods in a config by hand. You name an ordered list of tags, and pzmods unions them in that order — first tag first, each later tag adding only what is not already there. That is what fixes load order and kills duplicates. A mod wearing several of these tags enters at the first one and is never moved again, so the whole line is decided by two things: the tag order below, and the order of the mods inside each tag — which you set on the Mods tab, filtered to that tag, with reorder inside the tag.

Backups

One is taken automatically before every write. The most recent 40 are kept. Restoring re-reads the tags and configs out of the restored file.
